# 문서 파일 만들기 프롬프트

아래 내용을 ChatGPT·Claude·Gemini 같은 LLM 에 그대로 붙여 넣고, 맨 아래에 **템플릿 이름**과 **원문**을 넣으세요.
LLM 이 돌려준 코드를 `documents/새이름.js` 로 저장하고, `documents/manifest.js` 목록에 파일 이름을 더하면 화면에 나타납니다.

---

너는 notelayer 의 문서 파일을 만든다. notelayer 는 원문을 고치지 않고 그 위에 표시·설명 층을 얹어 보여 주는 도구다.
아래 규칙을 지켜 **자바스크립트 코드 한 덩어리만** 돌려줘. 설명 문장은 쓰지 마.

## 출력 모양

```js
window.NL_DOCS = window.NL_DOCS || [];
window.NL_DOCS.push({
  "id": "영문-소문자-하이픈",          // 다른 문서와 겹치지 않게
  "title": "문서 제목",
  "lang": "ko",                       // 원문 언어 (en, ko, ja …)
  "source": "출처 (URL 또는 설명)",
  "templates": ["템플릿 id"],
  "blocks": [
    { "p": 1, "text": "원문 첫 문단 그대로", "tr": "번역 (원문이 한국어가 아닐 때만)" }
  ],
  "memos": [],
  "annotations": {
    "템플릿 id": {
      "marks": [
        { "p": 1, "kind": "circle", "quote": "원문에 있는 글자 그대로" }
      ],
      "boxes": [
        { "p": 1, "label": "설명 종류", "text": "설명 첫 줄", "pre": "글자 그림 (선택)", "answer": "답 (풀어 보기일 때만)" }
      ],
      "concepts": {
        "topic": "문서 주제",
        "nodes": [
          { "id": "a", "term": "개념 이름", "role": "문제", "parent": null, "def": { "p": 1, "quote": "정의 문장 안의 원문 일부" }, "match": ["본문 낱말"] },
          { "id": "b", "term": "하위 개념", "role": "구성 요소", "parent": "a", "def": { "p": 2, "quote": "…" }, "match": ["…"] }
        ],
        "links": [{ "from": "b", "to": "a", "label": "해결" }]
      }
    }
  }
});
```

## 반드시 지킬 것

1. **원문은 한 글자도 바꾸지 않는다.** 문단을 나누기만 하고 `blocks[].text` 에 그대로 넣는다. 머리글·광고·메뉴 같은 본문 아닌 글은 뺀다.
2. **`quote` 는 그 문단 `text` 안에 글자 그대로 있는 부분이어야 한다.** 띄어쓰기·문장부호까지 같아야 화면에서 제자리에 붙는다. 너무 짧으면(한두 글자) 엉뚱한 곳에 붙을 수 있으니 뜻이 서는 단위로 고른다.
3. **모양의 뜻은 고정이다.** `circle` = 핵심어(짧은 용어), `highlight` = 중요한 문장, `wave` = 확인이나 보충이 필요한 곳.
4. **많이 칠하지 않는다.** 문단당 표시 1-2개, 문서 전체에 문단 수의 1.5배 정도까지. 문서 앞쪽에 몰리지 않게 끝까지 고르게.
5. **설명(`boxes`)의 `label` 은 아래 템플릿의 설명 종류 중에서만 고른다.** `text` 는 한두 문장, 더 필요하면 `pre` 에 글자 그림이나 비교를 넣는다.
6. **모르는 것은 지어내지 않는다.** 근거가 확실하지 않은 보충·정정은 쓰지 않는다. 숫자·조문·명령어는 확실한 것만 쓴다.
7. HTML 태그를 쓰지 않는다. 모든 값은 글자다.
8. 원문이 한국어가 아니면 문단마다 `tr` 에 자연스러운 한국어 번역을 넣는다.
9. **`concepts` 는 개념 구조도다.** 주요 개념 5-14개를 고르고, 하위 개념·구성 요소면 `parent` 에 상위 개념 id 를, 동등한 개념이면 같은 `parent` 를 준다. 맨 위는 `parent: null`. 여러 개념을 묶는 분류 개념(`def` 없음)을 만들어도 된다. 위아래가 아닌 관계(해결, 원인, 대비, 전제)는 `links` 에 짧은 `label` 로. `def.quote` 는 그 개념을 설명하는 문장 안의 원문 글자 그대로 일부, `match` 는 본문에서 그 개념을 가리키는 낱말(원문 표기 그대로)이다.

## 템플릿

| id | 이름 | circle | highlight | wave | 설명 종류 (label) | 추가 규칙 |
|---|---|---|---|---|---|---|
| exam | 시험공부 노트 | 핵심어 | 외울 문장 | 헷갈리기 쉬운 곳 | 핵심, 그림으로, 헷갈림 주의, 직접 풀어 보기 | 직접 풀어 보기는 `text` 에 질문, `answer` 에 답 |
| tech | 기술 문서 입문 | 모르는 용어 | 꼭 알아야 할 문장 | 글이 건너뛴 전제 | 용어 풀이, 먼저 알아야 할 것, 보충, 따라 해 보기 | 따라 해 보기는 실제로 되는 절차만 |
| contract | 계약서·약관 | 의무·금액·기한 | 꼭 읽을 조항 | 불리할 수 있어 확인이 필요한 조항 | 쉬운 말, 확인 필요, 물어볼 질문 | 법률 판단을 하지 않는다. "확인 필요" 까지만 쓰고 근거 조문을 단다 |
| onboarding | 회사 문서 온보딩 | 사내 용어 | 꼭 지킬 절차 | 예외·주의 | 용어 풀이, 담당자 메모, 자주 하는 실수 | 담당자 메모는 사람이 쓴 것으로 두고 `"by": "이름"` 을 단다 |
| review | 첨삭·피드백 | 살릴 강점 | 잘 쓴 문장 | 고칠 곳·근거가 약한 주장 | 지적, 고친 예시(제안), 칭찬 | 고친 예시는 `pre` 에 "고치기 전 / 고친 예시" 로 |
